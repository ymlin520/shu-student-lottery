# 世新在校生抽獎系統

在校生用學校帳號密碼（世新 SSO）登入即完成報名 ＋ 大樂透風格的現場抽獎系統。
視覺採用世新大學 70 週年主視覺，暗紅底、亮金、粗黑體，並以「在校生場 STUDENTS」標籤與浮水印和[校友版](https://github.com/ymlin520/shu-alumni-lottery)區分。

零相依套件，只要有 Node.js 就能跑；資料存在本機單一 JSON 檔。

```
學生掃 QR Code → 輸入學號／校園帳號與密碼 → SSO 驗證通過即完成報名
→ 活動現場投影抽獎畫面 → 按下開始抽獎 → 彩球慢速攪拌 → 畫面中上方先出現系所 → 3 秒後姓名一個字一個字出現
```

## 四個頁面

| 路徑 | 用途 | 需要密碼 |
|---|---|:--:|
| `/` | **報名頁**。學生輸入學號／校園帳號與密碼，SSO 驗證通過即完成報名 | 學校帳密 |
| `/draw` | **抽獎畫面**。投影用，彩球慢速攪拌後掉出中獎球，畫面中上方先顯示系所、3 秒後姓名超大字一個字一個字出現 | 管理密碼 |
| `/admin` | **後台**。抽獎設定、中獎紀錄、名單管理、匯出 CSV、SSO 狀態 | 管理密碼 |
| `/design` | **設計後台**。改前台的顏色、Logo、背景圖、字型、尺寸、所有文字，右側即時預覽 | 管理密碼 |

三個管理頁使用同一組管理密碼。後台與抽獎畫面共用登入（12 小時內有效）；**設計後台需要另外登入**，2 小時後自動登出。

## 快速開始

需求：[Node.js](https://nodejs.org/) 20 以上（開發環境為 24）。不需要 npm install。

```bash
PORT=8124 node server.js
```

啟動後：

- 網站在 http://localhost:8124
- 首次啟動會自動產生管理密碼，寫在 `admin-password.txt`，終端機也會印出來
- 沒有 `sso-config.json` 時自動使用 **SSO 測試模式**（任何帳密都會通過，回傳假資料），前後台會顯示紅色警告

Windows 可以直接雙擊 **`啟動.bat`**，它會啟動伺服器（port 8124）並開一條 Cloudflare 臨時通道。

## SSO 介接

介接世新大學的 SSO Web Service（`ServSSO.asmx` 的 `SetUrlLog`），詳細步驟見 **`SSO設定說明.txt`**。

1. 向圖資處系統組申請**廠商帳號 id1、廠商密碼 id2**。
2. 複製範本：`sso-config.example.json` → `sso-config.json`（此檔不進版控）。
3. 在 `sso-config.json` 把 `mode` 改成 `shu`，填入 `id1`、`id2`；`env` 填 `test`（測試機）或 `prod`（正式機）。
4. 重新啟動。後台上方會顯示目前連的是測試機或正式機。

| 模式 | 說明 |
|---|---|
| `mock` | 測試模式，任何帳密都通過，回傳假學生資料 |
| `shu` | 世新 SSO。測試機 `netoffice.shu.edu.tw`、正式機 `ap0.shu.edu.tw` |
| `api` | 其他 JSON 格式的認證 API（保留給日後擴充） |

- SSO 回傳逗號分隔 15 個欄位。**在校生判斷**：第 13 欄「登入身分」＝ 2（學生）**且**第 7 欄「是否為在校生」＝ 1，兩者都成立才能報名。
- 存進後台名單的是第 2 欄**姓名**與第 14 欄**學號**（登入員工編號或學號），另存系所（第 11 欄）與 Email（第 15 欄）。
- `onlyCurrentStudent: true`（預設）時才做上述判斷；離校生、純教職員會被擋下，以教職員編號登入的在校生會被提示改用學號登入。
- 世新回傳的錯誤訊息會附帶使用者輸入的密碼，寫入 log 前會自動遮成 `***`。
- 回傳 `Error:` 開頭時，詳細原因只寫進伺服器 log，學生只看到「系統登入失敗」。
- 同時支援兩種登入方式：
  - **密碼法**（開發階段）：學生在報名頁直接輸入帳密。
  - **認證Key 法**（上線後）：學校入口以 POST 將 `AuthID`／`AuthKey` 送到 `/sso/accept`，驗證後導回報名頁顯示結果；登出頁為 `/sso/logout`。申請時請把這兩個網址交給系統組。

## 活動當天的流程

1. **開放報名**：把 `/` 的網址做成 QR Code 發給學生。後台「開放學生報名」要保持開啟。
2. **截止報名**：活動開始前關掉開關，報名頁就會顯示「報名已截止」。
3. **投影**：另一台電腦開 `/draw`，登入後按右上角「全螢幕」。
4. **抽獎**：按「開始抽獎」，彩球**慢速**攪拌後掉出中獎球，抽獎機變暗，**畫面中上方**先顯示「恭喜抽中」與**系所**（同名時靠系所區分），**3 秒後**姓名以超大字**一個字一個字**出現，最後畫面閃光並灑兩波彩帶；按鈕在揭曉時移到畫面最下方。
   - 中獎者由伺服器以 `crypto.randomInt` 決定，前端只負責播動畫。
   - 每位同學最多中獎一次。
5. **記錄**：中獎名單即時出現在 `/admin` 的「中獎紀錄」，抽錯可單筆「撤銷」。
6. **收尾**：後台「匯出 CSV」下載名單。

## 後台功能

### 抽獎設定

| 項目 | 說明 |
|---|---|
| 本輪獎項 | 選填。填了會記在中獎紀錄與 CSV，抽獎畫面不顯示 |
| 投影時遮蔽姓名中間字 | 開啟後中獎姓名顯示為「王○明」 |
| 開放學生報名 | 關閉後報名頁顯示「報名已截止」 |

改完要按 **「儲存設定」** 才生效，抽獎畫面約 4 秒內同步。

### 中獎紀錄

- 抽獎畫面抽出的人會自動出現（後台每 5 秒更新）。
- **撤銷**單筆，或 **↻ 重新抽獎（清空中獎紀錄）** 整批清空，被清掉的人回到待抽名單。

### 名單管理

- 統計：已報名、已中獎、待抽、後台補登筆數；可搜尋姓名、學號、系所、班級、Email、編號。
- **＋ 手動新增學生**：現場補登沒有帳號或 SSO 有問題的學生（學號、姓名、系所、班級、Email），會標記「後台補登」。
- **編輯**／**刪除**單筆；**清空名單**會連續確認兩次。
- **匯出 CSV**：UTF-8 with BOM，欄位為報名編號、學號、姓名、系所、班級、Email、來源、報名時間、最後登入、中獎獎項、抽出時間。

同一學號重複登入不會重複報名，只會更新最後登入時間；報名編號從 `S0001` 起跳。

## 設計後台

`/design` 左側修改、右側即時預覽，按「儲存」（或 Ctrl+S）才會套用到正式頁面。

| 分頁 | 內容 |
|---|---|
| 配色 | **一鍵色系**（紅底亮金、深藍金、紅金、藍金、墨綠金、紫金、黑金），以及底色、光暈、卡片、主色、按鈕文字、身分識別色等 15 項 |
| 抽獎機 | 外環三色階、球槽、5 種彩球顏色、中獎球顏色、**彩球數量**（預設裝滿 32 顆）、彩球大小 |
| **抽獎畫面** | **抽獎機大小滑桿**（預設佔畫面高度 56%，可調 25～75%），以及抽獎時的所有尺寸、位置與秒數：中獎姓名字級、系所字級、**姓名離頂端距離**、系所後等多久出姓名、姓名逐字間隔、攪拌時間、彩球轉速、揭曉時抽獎機亮度、揭曉底色濃度、標題字級、按鈕字級等（14 項）。切到這個分頁時，預覽會直接停在「抽獎揭曉」畫面，改了立刻看得到 |
| 圖片與 Logo | **上傳替換**左上角 Logo、抽獎機中心 Logo、分頁圖示、背景裝飾圖（可恢復預設或設為不顯示），以及 Logo 大小、背景透明度 |
| 字型與尺寸 | 內文／標題字型、卡片與按鈕圓角、登記／報名頁標題字級 |
| 報名頁文字 | 身分標籤、浮水印、標題、說明、欄位名稱與提示字、按鈕、個資說明、完成／已報名過／截止畫面（21 項） |
| 抽獎頁文字 | 身分標籤、浮水印、標題、轉盤中心字、按鈕、「恭喜抽中」、未提供系所時的文字等（11 項） |
| 進階 CSS | 自由撰寫 CSS，優先權最高 |

- 預覽另有「**抽獎揭曉**」畫面：不用等攪拌，直接顯示中獎姓名的樣子，方便調整位置與大小。
- 預覽可切換報名頁／報名完成／報名截止／已報名過／抽獎頁，以及電腦／手機寬度；預覽中的送出與抽獎都是假的。
- 上傳的圖片存在 `data/uploads/`（不進版控），限 PNG、JPG、GIF、WebP、SVG、ICO、5 MB 以內；以檔頭判斷格式，SVG 一律以沙盒 CSP 送出。
- 頁面一律透過 `/brand/logo`、`/brand/hub`、`/brand/favicon`、`/brand/bg` 取圖，換圖不用改程式。

## 個資與安全

這個 repo 是公開的，請注意：

- **`.gitignore` 已排除 `data/`、`admin-password.txt`、`sso-config.json`**：報名資料、管理密碼、世新廠商帳密都不會進版控。
- **學生密碼只即時轉送給學校認證系統，不寫進 `db.json`，也不寫進任何 log**。存下來的只有學號、姓名、系所、班級、Email 與時間。
- 認證Key 法導回時使用一次性、5 分鐘有效的代碼取結果，個資不放在網址上。
- SSO 登入每個 IP 每分鐘 10 次、後台登入每分鐘 10 次。
- 管理密碼比對使用 `crypto.timingSafeEqual`；登入以 HttpOnly + SameSite=Strict 的 Cookie 維持 12 小時。
- **設計後台 `/design` 需要單獨登入**：就算已經登入後台或抽獎畫面，進設計後台仍要再輸入一次密碼；設計後台的登入 2 小時後自動失效、不會延長，右上角有「登出」。設計相關 API（讀取／儲存設計、上傳圖片）只接受設計後台的登入。

## API 一覽

前台

| 方法 | 路徑 | 說明 |
|---|---|---|
| `GET` | `/api/status` | 活動標題、是否開放報名、報名人數、SSO 狀態 |
| `POST` | `/api/login` | 密碼法：SSO 驗證並報名 |
| `POST` | `/sso/accept` | 認證Key 法：學校入口 POST `AuthID`／`AuthKey` |
| `GET` | `/api/sso-result?t=` | 認證Key 法導回後取結果（一次性） |
| `GET` | `/sso/logout` | 供學校入口呼叫的登出頁 |

後台（需 `sid` Cookie）

| 方法 | 路徑 | 說明 |
|---|---|---|
| `POST` | `/api/admin/login` / `logout` | 登入、登出 |
| `GET` | `/api/admin/state` | 設定、名單、中獎紀錄、SSO 狀態 |
| `POST` | `/api/admin/settings` | 儲存獎項、遮蔽姓名、開放報名 |
| `GET` | `/api/admin/draw-info` | 抽獎畫面用的輕量狀態 |
| `POST` | `/api/admin/draw` | 抽出一位中獎者 |
| `DELETE` | `/api/admin/winners/:id` | 撤銷單筆中獎 |
| `POST` | `/api/admin/winners/reset` | 重新抽獎（清空中獎紀錄） |
| `POST` | `/api/admin/entries` | 手動新增學生 |
| `GET` `PUT` `DELETE` | `/api/admin/entries/:id` | 讀取、修改、刪除 |
| `POST` | `/api/admin/entries/reset` | 清空名單 |
| `GET` | `/api/admin/export.csv` | 匯出 CSV |
| `GET` `POST` | `/api/admin/design` | 讀取／儲存設計設定 |
| `POST` | `/api/admin/upload?slot=logo\|hub\|favicon\|bg` | 上傳圖片 |

圖片（不需登入）：`GET /brand/:slot`（加 `?default` 取預設圖）、`GET /uploads/:file`。

## 常見問題

**學生說帳密正確卻登入失敗？**
看伺服器 log 的 `[登入失敗]` 那行，會記錄 SSO 回傳的原因（不含密碼）。常見原因是非在校生身分、測試機只接受系統組的測試帳號，或廠商帳密填錯。

**重新登入會不會重複報名？**
不會，以學號判斷，重複登入只更新最後登入時間，畫面顯示「你已經報名過了」。

**手動編輯 db.json 要注意什麼？**
伺服器啟動時會把檔案讀進記憶體，必須先停止伺服器再編輯，否則會被覆寫。

**改了程式沒反應？**
`public/` 下的頁面每次請求都重新讀檔，重新整理即可；改 `server.js`、`sso.js`、`design-defaults.js`、`sso-config.json` 要重新啟動。
